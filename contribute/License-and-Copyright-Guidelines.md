# License and Copyright Guidelines

## Purpose
These guidelines specify how code contributors, Committers, and PMC members of the openJiuwen community handle the license and copyright statements of repositories and source code files, covering the following parts:
1. LICENSE file
2. NOTICE file
3. Copyright and license headers

## Scope
These guidelines apply only to the openJiuwen community. They do not apply to scenarios in which the openJiuwen project is used by individuals or enterprises to develop other products, nor to scenarios involving the distribution of third-party open-source software.

## Improvements and Revisions to This Document
1. This document is drafted and maintained under the leadership of the openJiuwen PMC. The latest version of this document can always be found [here](License-and-Copyright-Guidelines.md).
2. Any addition, modification, or deletion of the rules covered in this document must be tracked. Please enter the tracking system.
3. The final rules are finalized by the PMC after thorough discussion within the community.

## LICENSE File
1. Each open-source repository must contain clearly described license information, and the license must be consistent with the overall license rules of openJiuwen. For example, the agentcore open-source repository uses the Apache License 2.0.
2. The license file of each open-source repository must be in plain-text format, placed in the root directory of the code repository, and contain the full text of the license. It must be named "LICENSE" without any suffix such as ".txt" or ".md".
3. If different source code within an open-source repository contains multiple licenses, describe the primary license in a file named "LICENSE". Other licenses should be named in the form "LICENSE-LicenseType-Remark" and placed either in the root directory of the repository or in the root directory of the corresponding source code. At the same time, the primary license file must describe the location of each license file and the scope and scenarios to which it applies.
4. The license file of each open-source repository must cover all files within that repository. Ensure that the scope of each license is described accurately and concisely, and do not include unnecessary information such as licenses for other source code that is not published in this repository. For example, licenses of dependency software that must be downloaded separately should not be included in the repository or in the license information.
5. If an open-source repository is distributed in binary form, ensure that the license file is located in the conventional location for its distribution format, such as the top-level directory of the release folder or archive. For ".jar" files, the license may be located in the META-INF directory.

## NOTICE File
1. If the distributed binary files contain third-party open-source software, provide a file named "NOTICE". The NOTICE file must, in plain-text format, describe the names, software versions, rights-holder statements, and License information of all included third-party open-source software.
2. The NOTICE file is typically placed in the top-level directory of the release folder or archive. For ".jar" files, the license may be located in the META-INF directory.


## Copyright and License Headers
1. In principle, all files in an open-source repository should contain appropriate copyright and license header statements, except in the following scenarios:
   * Adding copyright and license statements would affect the function of the file. For example, JSON files do not support comments, so copyright and license headers need not be added.
   * Files generated by tools that contain a description indicating the file was automatically generated by a tool.
   * Short documentation files intended for users to read, where adding a copyright and license header would affect their readability, such as README files.

2. The copyright and license header statements take the following form:

   - The copyright statement format is as follows:

   ```
   Copyright (C) [Year of first release]-[Year of current version release] [Copyright owner]
   ```
   - The license header statement format is as follows, subject to the specific license content:

   ```
   Apache License Version 2.0 license header:
   Licensed under the Apache License, Version 2.0 (the "License");
   you may not use this file except in compliance with the License.
   You may obtain a copy of the License at

   Unless required by applicable law or agreed to in writing, software
   distributed under the License is distributed on an "AS IS" BASIS,
   WITHOUT WARRANTIES OR CONDITIONS OF ANY KIND, either express or implied.
   See the License for the specific language governing permissions and
   limitations under the License.

   BSD-3-Clause license header:
   Redistribution and use in source and binary forms, with or without modification,
   are permitted provided that the following conditions are met:

   1. Redistributions of source code must retain the above copyright notice, this list of
      conditions and the following disclaimer.

   2. Redistributions in binary form must reproduce the above copyright notice, this list
      of conditions and the following disclaimer in the documentation and/or other materials
      provided with the distribution.

   3. Neither the name of the copyright holder nor the names of its contributors may be used
      to endorse or promote products derived from this software without specific prior written
      permission.

   THIS SOFTWARE IS PROVIDED BY THE COPYRIGHT HOLDERS AND CONTRIBUTORS
   "AS IS" AND ANY EXPRESS OR IMPLIED WARRANTIES, INCLUDING, BUT NOT LIMITED TO,
   THE IMPLIED WARRANTIES OF MERCHANTABILITY AND FITNESS FOR A PARTICULAR
   ```

3. Note that the year in the copyright header is the year in which the work was released externally. If it is the first release, only the release year is required. If it is not the first release, use the format "Year of first release-Year of current version release".

4. The copyright owner is a legal entity, which may be an individual or a company. If you are contributing code on behalf of a company, please state the company's legal entity.

5. The license header information must be consistent with the license information of the open-source repository. If a file is under a dual license, its license header must clearly state the applicable conditions of each license and include the license header descriptions defined by each license in the file's license header.
