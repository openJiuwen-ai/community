# 各仓资料体系治理自查清单

本清单配合 [各仓资料体系治理规范](../各仓资料体系治理规范.md) 使用，供各 SIG 对照检查本仓文档达标情况。

> **说明：**
> 每项标记【规则】为必须达标，标记【建议】为可选达标。自查时逐条核对，未达标项列入整改计划。

## 一、最小闭环

| 序号 | 检查项 | 类型 | 达标 | 说明 |
| -------- | -------- | -------- | -------- | -------- |
| 1.1 | 安装指南存在且可用 | 【规则】 | [ ] | 用户照步骤可完成安装 |
| 1.2 | Quick Start 存在且可运行 | 【规则】 | [ ] | 示例代码可直接复制运行 |
| 1.3 | examples 示例工程存在 | 【规则】 | [ ] | clone 仓后有可运行的示例 |
| 1.4 | 新用户 30 分钟跑通实测 | 【建议】 | [ ] | 3 至 5 名新用户完成计时跑通 |

## 二、README 七段

| 序号 | 检查项 | 类型 | 达标 | 说明 |
| -------- | -------- | -------- | -------- | -------- |

| 2.2 | 核心特性段落存在 | 【规则】 | [ ] | 三至五条特性 |
| 2.3 | 相关文档段落存在 | 【规则】 | [ ] | 极简链接段落，指向仓内 docs、examples 等 |
| 2.4 | 环境要求段落存在 | 【规则】 | [ ] | OS、语言版本、依赖表 |
| 2.5 | 安装指南段落存在 | 【规则】 | [ ] | 极简安装命令 |
| 2.6 | Quick Start 段落存在 | 【规则】 | [ ] | 复制即跑的示例代码 |
| 2.7 | License 段落存在 | 【规则】 | [ ] | 明确标注开源许可证 |

## 三、docs 四类框架

| 序号 | 检查项 | 类型 | 达标 | 说明 |
| -------- | -------- | -------- | -------- | -------- |
| 3.1 | tutorial 目录存在 | 【规则】 | [ ] | 教程类文档有归属目录 |
| 3.2 | how-to 目录存在 | 【规则】 | [ ] | 操作指南类文档有归属目录 |
| 3.3 | reference 目录存在 | 【规则】 | [ ] | 参考类文档有归属目录 |
| 3.4 | explanation 目录存在 | 【规则】 | [ ] | 解释类文档有归属目录 |
| 3.5 | 每篇文档归属单一类别 | 【规则】 | [ ] | 不混合多个类别 |

## 四、目录组织六规则

| 序号 | 检查项 | 类型 | 达标 | 说明 |
| -------- | -------- | -------- | -------- | -------- |
| 4.1 | 编号规则达标 | 【规则】 | [ ] | Tutorial 有数字前缀，其余不编号 |
| 4.2 | 归位规则达标 | 【规则】 | [ ] | docs 与 design 分离（如有 design），无临时文件残留 |
| 4.3 | 命名规则达标 | 【规则】 | [ ] | kebab-case，语义化，同仓风格统一 |
| 4.4 | 一文件一主题达标 | 【规则】 | [ ] | 单篇标题数不超过 20 |
| 4.5 | 双语规则达标 | 【规则】 | [ ] | docs/zh/ 为中文权威源，docs/en/ 为英文跟随，结构对称 |
| 4.6 | LICENSE 仓根达标 | 【规则】 | [ ] | LICENSE 文件在仓根目录 |
| 4.7 | documents 改名为 docs | 【规则】 | [ ] | 如当前用 documents/，已改为 docs/ |
| 4.8 | 内部设计文档有导航链接 | 【建议】 | [ ] | 如仓有 design/ 目录，其中文档在 docs/ 的 explanation 中有链接 |

## 五、文档导航

| 序号 | 检查项 | 类型 | 达标 | 说明 |
| -------- | -------- | -------- | -------- | -------- |
| 5.1 | docs/README.md 存在 | 【规则】 | [ ] | 文档介绍与导航入口，说明覆盖范围并按四类列出链接 |

## 六、质量加成

| 序号 | 检查项 | 类型 | 达标 | 说明 |
| -------- | -------- | -------- | -------- | -------- |
| 6.1 | 单篇文档字节合理 | 【建议】 | [ ] | 无"少而长"或"多而碎"极端 |
| 6.2 | API 文档覆盖率不低于 80% | 【建议】 | [ ] | 已覆盖公开 API 类数 / 公开 API 类总数 |
| 6.3 | 文档更新时延不超过 30 天 | 【建议】 | [ ] | 最后更新与代码最后提交间隔 |
| 6.4 | 每仓 3 至 5 名新用户跑通实测 | 【建议】 | [ ] | 30 分钟跑通基准 |
